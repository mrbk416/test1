# Запись машин на приёмку склада

Бэкенд для экранов: календарь склада, загрузка Excel с VIN и результат записи.

**Стек:** Python 3.12, Django 5.2, Django Ninja (Swagger), PostgreSQL 16, PyJWT, openpyxl, httpx.

## Запуск

Нужны [uv](https://docs.astral.sh/uv/) и Docker.

```bash
cp .env.example .env               # при желании поменять JWT_SECRET на длинную случайную строку
docker compose up -d               # PostgreSQL на порту 55490
uv sync                            # зависимости
uv run python manage.py migrate
uv run python manage.py seed       # тестовые данные + sample_vins.xlsx
uv run python manage.py issue_tokens
uv run python manage.py runserver
```

- Swagger: http://localhost:8000/api/docs. Нажмите **Authorize** и вставьте токен из `issue_tokens` (без слова `Bearer`).
- Swagger заглушки учёта: http://localhost:8000/accounting-stub/docs

Сгенерировать длинный `JWT_SECRET`:

```bash
uv run python -c "import secrets; print(secrets.token_urlsafe(48))"
```

## Авторизация

Логина нет. Каждый эндпойнт `/api/...` требует заголовок `Authorization: Bearer <JWT>`.

- Проверяются подпись (`JWT_SECRET`, алгоритм `JWT_ALGORITHM`) и срок `exp`.
- Обязательные поля токена: `sub` (строка), `org_id` (число), `org_type` (`company` или `distributor`).
- Нет токена, неверная подпись, истёк срок, нет поля или неизвестный `org_type` → **401**.

Права:
- `company` (Астана Моторс) видит и записывает на все склады;
- `distributor` — только на свои. Чужой склад отвечает **404**, как несуществующий.

`manage.py issue_tokens` играет роль сервиса авторизации. Он выпускает токены на 30 дней для каждой организации из базы: Астана Моторс и двух дистрибьюторов.

## Тестовые данные (`manage.py seed`)

Команда пересоздаёт данные с нуля. id организаций всегда 1, 2, 3, поэтому выпущенные токены остаются рабочими.

| id | Организация | Тип | Склады (лимит в день) |
|---|---|---|---|
| 1 | Астана Моторс | company | — |
| 2 | Степь Моторс | distributor | 1 Астана-1 (40), 2 Караганда (20) |
| 3 | Алатау Авто | distributor | 3 Алматы-2 (30), 4 Шымкент (25) |

Записи считаются от дня запуска `seed` («Д»):

| Склад | Д−10 | Д−3 | Д+1 | Д+2 | Д+3 | Д+4 |
|---|---|---|---|---|---|---|
| Астана-1 | 30 | 15 | 12 | 25 | **37** | 40 (полный) |
| Алматы-2 | | | 10 | 5 | | |

### Пример Excel: `sample_vins.xlsx`

Грузить на склад **Астана-1** на дату **Д+3**: там свободно 3 места из 40. Точную дату `seed` печатает в конце.

| Строка | VIN | Ожидаемый результат |
|---|---|---|
| 2 | LVVDB21B4RD012401 | Записана |
| 3 | LVVDB21B4RD012402 | Записана |
| 4 | Z94C241BBRR10887 | Неверный VIN — 16 символов |
| 5 | XWEPC81BDR0004421 | Нет в учёте |
| 6 | VIN, уже записанный на Алматы-2 | Уже есть активная запись |
| 7 | LVVDB21B4RD012401 | Повторяется в файле (строка 2) |
| 8 | Z94C241BBRR108880 | Записана (последнее место) |
| 9 | Z94C241BBRR108881 | Не хватило мест |
| 10 | Z94C241BBRR108882 | Не хватило мест |

Итог: записано 3 из 9. Повторная загрузка того же файла вернёт 409 `no_free_slots`, потому что день станет полным. Чтобы повторить проверку, запустите `seed` ещё раз.

## Эндпойнты

Все пути начинаются с `/api`, все требуют токен. Даты в формате `YYYY-MM-DD`.

### `GET /api/warehouses`: список складов

Склады, видимые организации из токена.

```json
[
  {"id": 1, "name": "Астана-1", "daily_limit": 40, "distributor": {"id": 2, "name": "Степь Моторс"}}
]
```

### `GET /api/warehouses/{warehouse_id}/availability?date=2026-11-30`: свободные места на дату

Для «свободно N из M» после выбора склада и даты.

```json
{"date": "2026-11-30", "daily_limit": 40, "booked": 37, "free": 3, "can_book": true}
```

`can_book` = есть свободные места **и** дата не раньше сегодня.

Ошибки: 404 — склад не найден или чужой; 422 — нет даты или неверный формат.

### `GET /api/warehouses/{warehouse_id}/calendar?month=2026-11`: календарь на месяц

В `days` все дни месяца по порядку, включая дни без записей (`booked: 0`). Можно смотреть любой месяц, в том числе прошлый.

```json
{
  "warehouse": {"id": 1, "name": "Астана-1", "daily_limit": 40, "distributor": {"id": 2, "name": "Степь Моторс"}},
  "month": "2026-11",
  "days": [
    {"date": "2026-11-01", "booked": 0, "free": 40, "can_book": false},
    {"date": "2026-11-30", "booked": 37, "free": 3, "can_book": true}
  ]
}
```

Ошибки:
- 400 `{"detail": "..."}` — `month` не в формате `YYYY-MM` или месяц не 01–12;
- 404 — склад не найден или чужой;
- 422 — нет `month`.

### `GET /api/bookings/template`: шаблон Excel

Отдаёт файл `template.xlsx` с заголовком `VIN` в первой строке.

### `POST /api/warehouses/{warehouse_id}/bookings`: записать машины из Excel

Запрос `multipart/form-data`:

| Поле | Тип | Описание |
|---|---|---|
| `date` | строка `YYYY-MM-DD` | дата приёмки |
| `file` | файл `.xlsx` | первая строка — заголовки, среди них `VIN` |

#### Ответ 200

Возвращается всегда, когда файл обработан, даже если записано 0 машин.

```json
{
  "warehouse": {"id": 1, "name": "Астана-1", "daily_limit": 40, "distributor": {"id": 2, "name": "Степь Моторс"}},
  "date": "2026-11-30",
  "total": 9,
  "booked_count": 3,
  "daily_limit": 40,
  "free_after": 0,
  "rows": [
    {"row": 2, "vin": "LVVDB21B4RD012401", "status": "booked", "message": "Записана"},
    {"row": 7, "vin": "LVVDB21B4RD012401", "status": "duplicate_in_file", "message": "Повторяется в файле (строка 2)", "duplicate_of_row": 2}
  ]
}
```

| Поле | Что значит |
|---|---|
| `total` | сколько строк с VIN в файле (пустые не считаются) |
| `booked_count` | сколько записано |
| `free_after` | сколько мест осталось на эту дату после записи |
| `rows[].row` | номер строки как в Excel (заголовок — строка 1) |
| `rows[].duplicate_of_row` | номер первой строки с этим VIN; есть **только** у статуса `duplicate_in_file`, у остальных строк поля нет совсем (не `null`) |

Статусы строк:

| `status` | `message` |
|---|---|
| `booked` | Записана |
| `invalid_vin` | Неверный VIN — N символов |
| `duplicate_in_file` | Повторяется в файле (строка N) |
| `not_found` | Нет в учёте |
| `already_booked` | Уже есть активная запись |
| `no_slots` | Не хватило мест |

#### Ошибки на весь файл

Если такая ошибка случилась, ничего не записывается. Формат ответа `{"code": "...", "message": "..."}`, фронт различает причины по `code`.

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `past_date` | дата раньше сегодня |
| 409 | `no_free_slots` | на эту дату нет свободных мест (проверяется до чтения файла) |
| 400 | `no_vin_column` | в первой строке нет колонки `VIN` (или файл пустой) |
| 400 | `too_many_rows` | больше 200 строк с VIN; в ответе ещё `rows_count` — сколько строк в файле |
| 503 | `accounting_unavailable` | сервис учёта не ответил или ответил ошибкой |
| 404 | — | склад не найден или чужой (`{"detail": "..."}`) |
| 401 | — | нет токена или он невалидный |
| 422 | — | нет `date` или `file`, неверный формат даты (`{"detail": [...]}` от Django Ninja) |

## Как обрабатывается файл

1. Склад виден организации, иначе 404.
2. Дата не в прошлом → `past_date`.
3. На дату есть хотя бы одно место → иначе `no_free_slots`.
4. Читаем первый лист, ищем колонку `VIN` в первой строке (регистр и пробелы не важны, колонка может быть не первой).
5. Собираем VIN: пробелы по краям убираются, буквы приводятся к верхнему регистру, пустые строки пропускаются. Больше 200 → `too_many_rows`.
6. Проверяем каждую строку по порядку, первая неудача — причина:
   1. длина ровно 17 символов → `invalid_vin`;
   2. VIN не встречался выше в файле → `duplicate_in_file` (первое вхождение проверяется дальше как обычно);
   3. VIN есть в учёте (один запрос со всеми оставшимися VIN) → `not_found`;
   4. у VIN нет активной записи на любом складе и дату → `already_booked`.
7. В транзакции блокируем строку склада (`SELECT ... FOR UPDATE`), заново считаем свободные места и записываем подходящие машины по порядку строк. Кому не хватило — `no_slots`.

Сервис учёта вызывается до транзакции, чтобы не держать блокировку склада, пока ждём сеть.

## Сервис учёта

Контракт из задания:

```
POST {ACCOUNTING_URL}/api/v1/vehicles/lookup
Запрос:  {"vins": ["LVVDB21B4RD012401", "XWEPC81BDR0004421"]}   — до 200 VIN
Ответ:   {"found": ["LVVDB21B4RD012401"]}
```

В проекте есть заглушка по этому контракту: `/accounting-stub/api/v1/vehicles/lookup`, без авторизации. Она считает найденными все VIN, кроме `XWEPC81BDR0004421`. Адрес берётся из `ACCOUNTING_URL` в `.env`. Чтобы подключить настоящий сервис, достаточно поменять адрес.

Проверить ошибку 503: поставить в `.env` `ACCOUNTING_URL=http://localhost:9999` и перезапустить сервер.

## Модель данных

- `Organization` — `name`, `type` (`company` / `distributor`). `id` совпадает с `org_id` в токене.
- `Warehouse` — `name`, `distributor` (FK на Organization), `daily_limit`.
- `Booking` — `warehouse`, `date`, `vin`, `is_active`, `created_by` (`sub` из токена), `created_by_org`, `created_at`.
  - Частичный уникальный индекс `one_active_booking_per_vin`: `UNIQUE (vin) WHERE is_active`, то есть у VIN не больше одной активной записи. Это гарантирует база, даже при одновременных запросах.
  - Индекс `(warehouse, date)` — для подсчёта занятых мест.
